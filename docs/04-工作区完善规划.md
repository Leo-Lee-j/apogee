# 工作区完善规划

> 状态：提案  
> 日期：2026-08-07  
> 范围：应用入口、工作区窗口、数据隔离与本地目录管理。

## 1. 产品定义

Apogee 启动后固定进入**工作区入口界面**，不直接进入请求编辑器，也不自动打开上次使用的工作区。

用户从列表选择一个工作区后，才进入该工作区对应的接口窗口。接口窗口只服务一个工作区；集合、文件夹、接口、环境及运行态数据都必须有明确的 `workspaceId` 归属，不存在跨工作区的默认集合、默认环境或共享标签。

工作区定义为：**一个由用户拥有、可独立移动并可纳入 Git 的本地目录，是全部接口数据和会话状态的隔离边界。**

一期在同一个原生窗口内切换两种应用外壳：

```text
LauncherShell（入口界面） → WorkspaceShell（接口窗口）
```

这样符合“启动先选工作区”的产品体验，也避免同时常驻两个 WebView 破坏内存预算。逻辑上仍按两个窗口边界设计；后续扩展为“一工作区一原生窗口”时，不需要改变数据契约。

## 2. 核心原则

1. **入口是固定起点。** 每次冷启动都展示 Logo 和工作区列表，最近使用只影响排序，不自动跳转。
2. **选择后才加载。** 入口首帧不扫描集合、不加载环境、不恢复标签，点击工作区后才加载该目录。
3. **一个接口窗口只绑定一个工作区。** 工作期间不在顶栏直接热切换；要进入其他工作区，先安全退出当前接口窗口并返回入口。
4. **所有业务数据都有归属。** 集合、文件夹、接口、环境、历史、响应、活动环境和标签会话均按 workspace id 隔离。
5. **入口不承载业务状态。** 返回入口后必须清空当前工作区的内存投影，不能让旧树、旧环境或旧响应短暂出现在下一个工作区。
6. **路径由用户拥有。** 打开普通目录不会隐式初始化；从最近列表移除不会删除磁盘数据。

## 3. 现状与差距

当前已有工作区内部能力：

- `WorkspaceManifest` 以及集合、文件夹、请求、环境的 YAML 契约。
- Rust 仓库支持树加载及节点、请求、环境的基础 CRUD。
- 请求按需读取，集合树使用扁平快照，符合性能约束。
- 请求发送可以从当前工作区读取环境。

与目标模型的主要差距：

- 应用启动固定初始化并打开 `app_data_dir/workspace`，没有入口态。
- `AppBody` 默认挂载完整接口界面，入口和工作区外壳没有路由状态。
- 顶栏工作区按钮只是展示；上一版“在这里直接切换”的设想不再采用。
- Rust `AppState` 只有一个隐式当前仓库，IPC 没有 workspace id 防串写校验。
- `WorkspaceRepository::open` 会在缺清单时初始化目录，打开和创建没有安全边界。
- 标签自动保存、环境脏状态、响应状态和 UI store 没有退出工作区协议。
- 当前历史位于工作区目录的 `history/`，既污染 Git 目录，也没有独立运行态根目录。

## 4. 信息归属与隔离

| 数据 | 归属 | 存放位置 |
| --- | --- | --- |
| 工作区名称与 id | 工作区 | `apogee.yaml` |
| 集合 Collection | 工作区 | 用户工作区目录 |
| 文件夹 Folder | 工作区内的集合/文件夹 | 用户工作区目录 |
| 接口 Request | 工作区内的集合/文件夹 | 用户工作区目录 |
| 环境 Environment | 工作区 | 用户工作区目录 |
| 密钥与本机环境覆盖 | 工作区 + 本机 | 后续接系统钥匙串；不得明文进入 Git |
| 历史、响应体、索引、运行记录 | 工作区运行态 | AppData 下按 workspace id 分区 |
| 活动环境、展开节点、标签、布局 | 工作区会话态 | AppData 下按 workspace id 分区 |
| 工作区列表、最近访问时间 | 应用入口 | AppData 工作区注册表 |
| 主题、代理、证书、快捷键 | 应用级 | 应用设置 |

用户工作区目录：

```text
my-api-workspace/
├── apogee.yaml
├── .gitignore
├── collections/
│   └── <collection-id>/
│       ├── _collection.yaml
│       ├── <request-id>.yaml
│       └── <folder-id>/
│           ├── _folder.yaml
│           └── <request-id>.yaml
└── environments/
    └── <environment-id>.yaml
```

应用私有目录：

```text
AppData/Apogee/
├── workspaces.json
├── workspace-state/<workspace-id>.json
└── runtime/<workspace-id>/
    ├── history/
    ├── responses/
    └── index.sqlite
```

必须满足以下隔离不变量：

- 任何集合、文件夹、接口或环境只能通过当前 `WorkspaceSession` 访问。
- 所有写 IPC 同时携带 `workspaceId` 与 `sessionId`；Rust 校验二者均匹配当前会话。
- 节点 id 即使跨工作区碰撞，也不能被另一个工作区读取或修改。
- 退出时使 session 立即失效；晚到的自动保存只能返回 `WORKSPACE_SESSION_EXPIRED`。
- 注册表只保存工作区描述信息，不能缓存集合、接口或环境内容。
- 工作区 A 的树、标签、环境、响应、历史和布局不能成为工作区 B 的初始化默认值。

## 5. 应用状态与生命周期

应用外壳状态：

```ts
type AppShellState =
  | { kind: 'launcher' }
  | { kind: 'opening'; workspaceId: string }
  | { kind: 'workspace'; session: WorkspaceSession }
  | { kind: 'closing'; session: WorkspaceSession }
```

完整流程见 [工作区生命周期图](./diagrams/workspace-lifecycle.mmd)：

1. 启动只读取轻量工作区注册表并渲染入口。
2. 点击列表项后只读检查路径和清单，再建立候选仓库。
3. 校验成功后创建带随机 `sessionId` 的 `WorkspaceSession`。
4. 前端收到完整快照后才挂载 `WorkspaceShell`；加载期间保持入口布局并显示行内进度。
5. 从接口窗口返回时，停止发送，flush 请求和环境，保存会话态。
6. Rust 关闭 session，前端整体销毁工作区 stores，再显示入口。
7. 关闭失败时留在当前接口窗口并显示可操作错误，不进入半清空状态。

## 6. 入口界面设计

### 6.1 视觉方向

入口界面只出现两个主体：**Apogee Logo** 和**工作区列表**。不放欢迎标题、功能介绍、数据安全说明、营销卡片、插画、统计数字或快捷键教学。

视觉应安静、精确、有桌面工具质感：

- 使用现有明暗主题和色彩 token，背景保持纯净，不使用渐变、光球或装饰图案。
- 内容区最大宽度约 720px，在窗口内水平居中；纵向位置略高于几何中心。
- Logo 是首屏品牌信号，但不过度放大：图标约 40px，字标 24px，与列表间距 32px。
- 列表是一块连续表面，不把每个工作区做成独立漂浮卡片。
- 行高 56px，圆角不超过 6px；选中、悬停和键盘焦点使用克制的边框与背景变化。
- 字体不随视口缩放；工作区名 14px，路径 12px，路径中间省略。
- 动效只用于列表进入和状态变化，时长不超过 150ms。

### 6.2 布局草图

```text

│                                                        ─ □ × │
│                                                              │
│                     [ Apogee Logo ]                          │

│        │  用户服务                            最近使用 │      │
│        │  D:\work\user-service-api                    │      │

```

“新建”和“打开”作为列表尾部的命令行，仍属于工作区列表，不再增加第二个操作区。熟悉图标使用现有图标库；列表行末只在悬停或键盘聚焦时显示更多菜单。

### 6.3 列表行为

- 默认按 `lastOpenedAt` 倒序；点击整行进入对应接口窗口。
- 单击缺失目录不进入接口窗口，原位显示“目录不可用”，更多菜单提供“重新定位”和“移除记录”。
- 更多菜单只包含“在文件管理器中显示”“重新定位”“从列表移除”；不提供删除磁盘目录。
- 支持方向键移动、`Enter` 打开、`Delete` 仅触发移除记录确认。
- 列表为空时仍保持同一结构，只显示“新建工作区”和“打开本地工作区”两行，不另做空状态宣传页。
- 打开中仅锁定被点击行并显示小型进度，不让整个界面跳成全屏 loading。

### 6.4 接口窗口

进入后才挂载现有 `AppBody`、集合树、标签、请求编辑器和环境控件。顶栏显示当前工作区名称，但不提供直接切换下拉；点击工作区名称执行“返回工作区列表”，走完整关闭协议。

接口窗口标题建议为 `工作区名称 - Apogee`。恢复标签、活动环境和布局时，只读取该 workspace id 对应的会话文件。

## 7. 仓库与 IPC 边界

工作区操作必须拆开语义：

- `inspect(path)`：只读校验目录、清单、格式版本、id 和可写性，不创建文件。
- `create(path, name)`：只允许空目录或明确的新目录，原子创建初始结构。
- `open(workspaceId)`：从注册路径打开已有工作区并创建新 session。
- `close(sessionId)`：关闭当前工作区会话。
- `forget(workspaceId)`：只移除入口列表记录，绝不删除用户目录。

```ts
interface WorkspaceDescriptor {
  id: string
  name: string
  path: string
  writable: boolean
  lastOpenedAt?: number
  status: 'available' | 'missing' | 'invalid' | 'unsupported'
}

interface WorkspaceSession {
  workspaceId: string
  sessionId: string
  descriptor: WorkspaceDescriptor
}

interface WorkspaceSnapshot {
  session: WorkspaceSession
  nodes: WorkspaceNode[]
  environments: Environment[]
}
```

建议 IPC：

- `workspace_list(): WorkspaceDescriptor[]`
- `workspace_inspect(path): WorkspaceInspection`
- `workspace_create(path, name): WorkspaceSnapshot`
- `workspace_open(workspaceId): WorkspaceSnapshot`
- `workspace_close(sessionId): void`
- `workspace_relocate(workspaceId, path): WorkspaceDescriptor`
- `workspace_forget(workspaceId): void`
- `workspace_reveal(workspaceId): void`
- 现有读写命令统一附带 `workspaceId` 和 `sessionId`

错误使用稳定 code：`NOT_A_WORKSPACE`、`UNSUPPORTED_FORMAT`、`DUPLICATE_ID`、`PATH_MISSING`、`READ_ONLY`、`SESSION_EXPIRED`、`SAVE_BLOCKED`。

## 8. 实施阶段

### P0：工作区边界

- 将 `WorkspaceRepository::open` 拆为只读打开与显式创建。
- 快照加入 descriptor 和 session；仓库暴露 root、id、writable。
- 所有节点、请求、环境和历史操作经 session 校验。
- 将历史运行态迁到 `runtime/<workspace-id>`，或先抽象 runtime root。
- 补格式版本、重复 id、路径规范化、session 失效和跨工作区 id 碰撞测试。

完成标准：打开普通目录不产生文件；使用 A 的 session 不能读取或修改 B 的任何数据。

### P1：入口注册表与生命周期

- 实现原子写的 `workspaces.json` 及 list/create/open/close/relocate/forget IPC。
- `AppState` 从“启动即有默认仓库”改为“启动无工作区，打开后才有 session”。
- 启动不初始化仓库，只读取工作区描述列表。
- 旧 `AppData/workspace` 作为待迁移来源，不再作为永久默认工作区。

完成标准：每次启动必达入口；重启后列表存在但不会自动进入上次工作区。

### P2：前端双外壳与退出协议

- 增加顶层 `LauncherShell` / `WorkspaceShell` 状态，不依赖完整路由库。
- `workspace` store 区分注册表状态与当前 session 状态。
- `tabs` store 实现 `flushAll()` 和 `disposeWorkspace()`；保存计时器捕获 session id。
- `request`、`history`、`ui` 中的工作区状态实现统一 dispose/reset。
- 返回入口时先 flush，再使 session 失效，最后卸载接口外壳。

完成标准：A → 入口 → B 的全过程没有一帧显示 A 的集合、环境、标签或响应；晚到保存不会写入 B。

### P3：现代化入口界面

- 实现 Logo、连续工作区列表、列表尾部新建/打开命令行和异常状态。
- 目录选择插件延迟加载，不进入首屏 chunk。
- 实现键盘导航、行内 loading、重新定位、移除记录和文件管理器定位。
- 顶栏工作区名称改为“返回列表”入口，移除直接切换的下拉语义。
- 对旧单例仓库提供复制、校验、注册的显式迁移，原目录暂不删除。

完成标准：入口首屏只包含 Logo 与列表；鼠标和键盘均可完成创建、打开和进入工作区。

### P4：后续扩展

- 文件监听与 Git 外部变更热重载。
- 会话恢复、冲突处理、只读工作区。
- 一工作区一原生窗口；入口负责聚焦已打开窗口，避免同目录重复写。
- 多窗口同目录锁、拖拽移动、公开 Schema。

## 9. 验收矩阵

| 场景 | 必须验证 |
| --- | --- |
| 启动 | 有无工作区都显示入口；不读取集合或环境；不自动打开最近项 |
| 入口视觉 | 首屏只有 Logo 和连续列表；800x560 与常用桌面尺寸无重叠、截断或跳动 |
| 创建 | 空目录成功；非空普通目录不被改写；初始化中断可恢复 |
| 打开 | 合法 v1、缺清单、损坏 YAML、过新版本、重复 id、只读目录 |
| 退出 | 自动保存成功/失败、发送中、环境未保存、快速返回、旧 IPC 晚到 |
| 数据隔离 | 集合、文件夹、接口、环境、历史、响应、标签和布局均按 workspace id 隔离 |
| 列表 | 最近排序、目录移动/删除、重新定位、同路径去重、forget 不删除磁盘数据 |
| 迁移 | 复制后逐项校验；中断保留旧目录；重复迁移可识别 |
| 性能 | 入口首帧不加载接口外壳重组件；目录插件不进首屏 chunk；接口性能指标不回退 |

最高风险仍是静默串写，而不是入口列表不可用。实现顺序应先完成 Rust session 隔离和退出协议，再接入视觉界面。

## 10. 暂不纳入一期

- 云工作区、成员和权限。
- 自动 Git commit、push、pull。
- 打开普通目录后自动生成 `apogee.yaml`。
- 从入口删除工作区磁盘目录。
- 一个接口窗口同时挂载多个工作区。
- 同时常驻多个原生工作区窗口。

这些能力不会阻塞“启动选择工作区 → 进入独立接口窗口 → 安全返回入口”的完整闭环。
