# 功能完善度复评：编辑与迁移边界

日期：2026-11-19。评估基线：已推送的修复提交 `8612e65`。上一轮五项 P1 的实现和验证见 [首轮报告](./feature-completeness-assessment.md)。

本轮检查组合操作时，在上述基线上复现了 **4 项 P1 行为缺陷、2 项 P2 缺口**，随后已逐项完成六项修复。原始证据与行号保留在下文，均指修复前基线；当前实现和回归结果见文末“修复与验证”。诊断和回归均使用隔离数据目录、真实 Tauri/WebView2、产品界面、IPC facade 与本地 HTTP 接收端。

## 修复前问题与处理顺序

| 顺序 | 级别 | 问题 | 实际影响 |
| --- | --- | --- | --- |
| 1 | P1 | 切换 Body 类型清空原编辑 | JSON→none→JSON 后内容为空；绑定集合的请求还会自动保存这个变化 |
| 2 | P1 | Postman 导出遗漏上级认证 | 原请求继承集合 Bearer，导出再导入后不再发送 Authorization |
| 3 | P1 | Postman 导出未合并两处 Query | URL 自带查询串与参数表同时有值时，往返后丢失 URL 中的参数 |
| 4 | P1 | Postman 批量导入失败不回滚 | 第二个请求名称超长时，报错但留下集合和第一个请求 |
| 5 | P2 | 导入目录身份用斜杠拼接名称 | 单个文件夹 A/B 与嵌套 A→B 被合并，改变请求所在目录 |
| 6 | P2 | Cookie 会话未接入请求链 | 收到 Set-Cookie 后，同一工作区的下一次请求不自动携带 Cookie |

P1 表示已交付操作会丢失编辑、改变发送行为或留下失败半成品；P2 表示特定结构兼容问题或尚未交付的会话能力。本轮的导出问题与上一轮的 Body 导入修复属于不同边界，原有测试未覆盖这些组合。

## 1. P1：Body 类型切换需要保留各自草稿

证据：`src/components/request/RequestPanel.vue:346` 的 `setBodyType` 直接生成并替换唯一的 Body。切到 none 时只留下类型；从 none 切回 JSON 时，原对象已经没有 content，所以得到空字符串。GraphQL、binary 和表单转到其他类型也没有独立的类型草稿。表单之间的已有转换及文件行拒绝规则不能覆盖这些情况。

桌面复现：新建请求，填写包含 `body-fixture` 的非空 JSON，点击 Body→none→JSON。读取实际标签模型，结果为 JSON 类型但 content 为空，操作过程中没有确认或恢复入口。绑定请求的同一修改路径会触发自动保存；本次实际交互复现使用独立草稿，未把自动保存落盘视为另一次已完成的复现。

影响：用户临时关闭请求体、比较编码方式或误点类型，就会覆盖原编辑。现有恢复快照跟随最新 Body，无法承担类型切换的撤销功能。

验收：按请求身份保留各 Body 类型的有界草稿，往返切换恢复 JSON/raw、表单行及元数据、GraphQL 三个字段和 binary 路径；明确哪些切换执行转换、哪些恢复原草稿。与标签复用、保存、工作区隔离和恢复容量限制一起验证，不能新增无界并行缓存。

## 2. P1：Postman 集合导出遗漏继承认证

证据：`src/components/sidebar/Sidebar.vue:489` 的导出只读取请求；根 info/item 和子文件夹 item 均不读取容器认证。`src/features/requestAuth.ts:70` 将请求的 inherit 投影为无 auth 字段，导出物又没有上级 auth 可继承。

桌面复现：集合设置 Bearer，子请求选择继承；通过侧边栏真实“导出”菜单获取生成的 Blob，随后用导出的内容调用真实 Postman 导入 IPC 并发送副本。仅修改导出集合的显示名称，避免与来源同名；未修改请求内容。接收端结果：

| 项目 | 原请求 | 导出再导入 |
| --- | --- | --- |
| Authorization | `Bearer fixture-only-token` | 无 |
| 导出集合 auth | — | 缺失 |
| 导出请求 auth | — | 缺失 |

`fixture-only-token` 是隔离测试的合成值，未使用用户凭据。继承已经在真实发送链解析成功，因此不能将此问题归因于来源未配置。

验收：保留导出范围内的集合/文件夹认证，或在 Rust 中为导出请求生成等价认证表示；导出单个继承请求或子文件夹时也要处理范围外的上级来源。显式 noauth 和手写 Authorization 的优先级要保持；无法表示的网络设置等行为须给出警告。遍历和批量读取应在 Rust 完成，避免扩大目前的前端逐项 IPC 与递归拼装。

## 3. P1：Postman 导出遗漏 URL 原始 Query

证据：`src/features/postmanExport.ts:39` 只把 `spec.params` 写入 Postman 的 query 数组，同时把地址栏查询串留在 raw。`crates/apogee-core/src/postman.rs:220` 遇到显式 query 数组时以该数组为权威，移除 raw 中的查询串以避免重复发送。两段各自的行为组合后丢参。

桌面复现与第 2 项共用请求：地址栏为 `/echo?from=raw`，参数表有启用行 `extra=table`。

| 阶段 | 内容 |
| --- | --- |
| 原请求实际到达服务端 | `/echo?from=raw&extra=table` |
| 导出 raw | 包含 `?from=raw` |
| 导出 query 数组 | 仅 `extra=table` |
| 导出再导入后实际到达服务端 | `/echo?extra=table` |

验收：导出时生成一致的 URL/query 表示，完整保留两处参数的顺序、重复项、禁用状态与变量占位符，并正确处理 fragment。不能简单让导入器同时发送 raw/query，否则会重新引入重复参数和签名变化。用实际接收端校验往返结果。

## 4. P1：Postman 批量导入缺少整体事务

证据：`src-tauri/src/lib.rs:1379` 先正式创建集合，之后逐项创建文件夹、请求并保存；失败用 `?` 返回，未撤销之前已发布的内容。`src-tauri/src/state.rs:439` 的 `with_workspace_mutation` 提供会话校验和互斥访问，不提供整批磁盘回滚。

真实 IPC 复现：导入包含两个请求的集合，第一个名称正常，第二个名称为 121 个字符。结果返回“名称不能超过 120 个字符”，但再次加载工作区时新增了：

- 集合 `Assessment partial import`；
- 请求 `First valid request`。

影响：界面报失败时工作区已经改变；直接重试可能继续留下多个半成品。仅在导入前校验名称能够修复这一触发条件，不能解决后续写盘失败或中断。

验收：先在 Rust 构建完整导入计划并校验，所有文件写入暂存目录，按单个提交点发布集合与清单；失败或进程中断可恢复。覆盖中途名称/内容校验失败、写入失败和清单提交失败；失败前后节点及环境不变，重试不重复。既有 YApi 导入与本轮复制事务可作为实现参照。

## 5. P2：文件夹身份不能由名称用斜杠拼接

证据：`src-tauri/src/lib.rs:1401` 将导入目录的名称段以 `/` 拼成 HashMap key，所以单段 `[A/B]` 和两段 `[A, B]` 的身份相同。

真实 IPC 复现：集合同时包含一个名为 `A/B` 的文件夹，和嵌套结构 `A→B`，二者各有不同请求。导入后两个请求的 parentName 都为 `A/B`；嵌套请求没有留在原有目录中。

验收：用无歧义的段序列或来源节点身份表示目录，保留显示名称。覆盖斜杠、空白、相似名称和同名兄弟目录；同名兄弟目录的现有行为本次未单独复现，修复时应增加覆盖。

## 6. P2：Cookie 登录态尚未形成闭环

证据：`crates/apogee-core/src/cookies.rs:14` 有独立 CookieJar，但生产发送链没有调用它。`sendCookies/send_cookies` 当前出现在模型、IPC 投影和设置继承中，不驱动 Cookie 的吸收与发送；响应面板只展示 Set-Cookie。

真实发送复现：本地端点 `/set-cookie` 返回 `probe_session=fixture; Path=/; HttpOnly`；随后在同一工作区请求 `/needs-cookie`，请求模型显式设为 `sendCookies: true`。服务端收到的 Cookie 仍为空。设置字段由诊断代码写入标签模型；产品目前也没有会话 Jar 管理入口。

这属于尚未交付的会话能力，不表示手写 Cookie Header 或 API Key Cookie 无效。独立 CookieJar 原型也缺少过期字段和完整来源/匹配校验，不宜直接接入生产链。

验收：工作区隔离的接收→存储→发送→查看/编辑/删除闭环；提供请求级关闭行为，覆盖域、路径、过期、Secure、重定向和手写 Header 优先级；会话凭据不进入共享文件、普通历史或日志。

### 使用与容量边界

- Body 类型草稿仅保存在本机编辑恢复文件，不进入请求 YAML 或 Postman 导出；请求与容器恢复合计最多 100 项、8 MiB。切换前检查容量，超限保留当前 Body。干净绑定请求只恢复非活动类型，打开时重新读取磁盘认证与名称；已删除来源恢复为独立草稿，来源核验在 Rust 完成。恢复写入仍有 300ms 防抖。
- Cookie 入口位于请求设置中的“管理 Cookie 会话”；默认跟随工作区会话收发。关闭、切换或重开工作区即清空，不跨会话持久化。每工作区最多 300 项、每域 50 项、每项 4096 字节，超限移除最早项。Cookie 值不进入共享 YAML、普通历史或日志，管理界面默认隐藏。
- HTTP 配置连接池复用并限制最多 32 个客户端；管理操作和网络任务均绑定工作区会话，旧请求不能写入新工作区的 Jar。
- Auth 导出使用每请求等价配置，不保留原容器的继承结构；导出警告保留产品无法映射到 Postman 的设置边界。
