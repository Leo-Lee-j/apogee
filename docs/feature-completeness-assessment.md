# 功能完善度评估

评估与修复日期：2026-11-19。对象：当前工作树 Apogee 0.1.1，修复前基线提交 `d1fd24e`。

本报告依据产品设计、桌面入口、IPC、Rust 执行与持久化实现，以及本次实际运行的检查。以用户能否完成操作闭环判断交付状态；核心库函数、Spike 和规划不计为已交付桌面功能。初评之后已逐项实施五项 P1 的代码修复，当前状态和修复前证据分别记录如下。

## 总体判断

**日常 HTTP 调试主流程已经可用，本轮已补上关闭保护、复制保真、JSON 树分页、Postman 迁移和首屏体积门禁；自动化主要处于核心库阶段。**

请求编辑、保存、发送、取消、认证、工作区隔离、历史、更新等能力已有完整实现和回归基础。部分高级能力早于原路线图交付，例如 OAuth2 PKCE、刷新和 YApi 导入；不能只按版本号判断功能成熟度。

本轮修复及桌面回归已完成。随后对组合操作进行 [第二轮复评](./feature-completeness-assessment-round2.md)，在已推送提交 8612e65 上实际复现了 4 项新的 P1（Body 类型切换、导出继承认证、导出混合 Query、导入失败回滚）和 2 项 P2（导入目录身份、Cookie 会话）。应优先处理这些行为边界，并补充当前产物的启动与内存性能量测。现有测试通过不代表未覆盖的功能已经交付。

### 使用方式与边界

- 未绑定集合的脏请求关闭时可选择“保存草稿”；下次打开同一工作区恢复。本机恢复文件位于 AppData 的 `editor-recovery/<workspace_uuid>.json`，不进入可分享工作区。请求与容器草稿合计最多 100 项、文件最多 8 MiB，超限写入失败会阻止关闭并保留编辑。自动恢复写入防抖 300ms，异常终止仍可能丢失最后一个防抖窗口内的修改。
- 容器配置切换页面时保留未保存编辑；关闭配置或离开工作区时统一询问。恢复文件只保存请求编辑与容器配置，不保存响应、错误快照或完整标签会话。
- JSON 树每个展开路径只缓存当前一页，总计最多 12 页。到达展开上限时，可折叠分支或选择“仅查看”，继续逐层访问；支持返回上级和根节点。
- URL 中 `{{env:apiBase}}/users` 明确引用环境变量；已有 `{{id}}` 继续表示 Path 参数。Postman 普通 URL 变量导入时转换为显式环境语法，导出时转换回 Postman 语法；旧 `baseUrl`/`baseURL` 到环境 Host 的兼容转换会给出警告。
- Postman 脚本、集合/文件夹变量作用域、不支持的认证、文件引用及逐字段 Content-Type 会进入迁移警告。脚本不会执行，作用域不会自动迁移；外部文件仍需选择本机有效文件，警告不回显脚本或变量的敏感值。
- gzip 门禁只统计生产 manifest 入口的静态 JS/CSS，沿静态 imports 去重并逐文件使用 gzip level 9；不计动态分支。相比初评的 279,930 字节下降约 63.5%。这不能证明冷启动、内存、50 标签、大响应或安装包预算达标。

## 修复前的问题与验收依据（历史基线）

以下证据与行号对应修复前提交 `d1fd24e`，用于保留初评依据，不表示当前工作树仍有这些缺陷。当前状态见上表。

### P1：统一关闭与退出的数据保护

证据：

- `src/stores/tabs.ts:368` 的关闭保存只针对有 `nodeId` 的请求；`:457` 的 `flushAll` 同样跳过草稿，随后工作区 reset 会移除标签。
- `src/ipc/index.ts:1348` 的窗口关闭直接调用原生 `close()`；当前源码没有统一的 `onCloseRequested`/退出保存拦截。
- `src/components/sidebar/ContainerConfigPanel.vue` 的配置编辑保存在组件本地，依赖手动保存，没有统一脏状态或离开保护。

影响：快捷请求或用例调试标签编辑后关闭/切换工作区会丢失未保存内容；原生退出也绕过工作区的保存等待，尤其影响防抖窗口内的请求修改和未提交环境编辑。容器配置切走页面也可能丢失编辑。

完善标准：标签关闭、页面切换、工作区切换、窗口 X 和 Alt+F4 共用退出协议；提供保存/放弃/取消；保存失败保持原界面；草稿按工作区在本机持久化并可恢复。草稿存储须有容量边界，不能把敏感内容写入可分享目录。

### P1：集合/文件夹复制保持实际请求行为

证据：`src/stores/workspace.ts:628` 只创建容器、复制请求 spec 和用例，未读取并复制 `WorkspaceContainer.auth/settings`。`src-tauri/src/workspace.rs:1488` 创建集合时将认证设为 Inherit、网络设置设为默认值。

复现：给集合设置 Bearer 认证或自定义超时，让子请求使用继承，再复制集合。副本容器恢复默认配置，副本请求可能失去认证或改变超时/TLS 等行为。

完善标准：复制前后解析出的认证和网络设置等价；节点与用例使用新 ID；失败不留下可见半成品。将遍历与批量复制下沉 Rust，避免前端按集合规模计算、逐项 IPC。

### P1：JSON 树能访问全部子项

证据：`src/components/response/JsonTreeView.vue:20` 固定 `PAGE = 200`；`:28` 的读取始终使用 offset 0，加载后按路径缓存；模板没有下一页或加载更多入口，已展开节点通过普通 `v-for` 全量渲染。

复现：返回一个含 201 个元素的数组，切换树形视图。第 201 项无法通过树形视图访问；嵌套对象/数组也有同样限制。原文和保存文件仍是替代出口。

完善标准：显示总数与已加载数量，提供分页/加载更多及失败重试；访问到末项；展开大量节点时使用真正的虚拟列表，并保持缓存有界。

### P1：Postman 导入避免静默改变请求

证据：`crates/apogee-core/src/postman.rs:393` 的 `import_body` 仅处理 raw 和 urlencoded，其他 mode 返回 `Body::None`，该函数没有迁移警告通道。集合与文件夹的 `event` 脚本、集合变量也未进入导入结果。

影响：form-data、binary、GraphQL 集合可能显示导入成功，但发送时缺少原请求体；依赖预请求脚本和集合变量的请求无法直接工作。

另一个迁移边界：`vars.rs:55` 刻意不对 URL 做环境变量替换，将双花括号用于 Path；导入器只特殊转换 `{{baseUrl}}`/`{{baseURL}}`。普通 Postman URL 模板如 `{{apiBase}}/users` 因此不能按原有语义直接使用。修复时必须同时处理现有 Path 兼容，不能简单全局替换。

完善标准：覆盖现有产品支持的全部 Body 类型；不支持的脚本、变量、认证或文件引用必须逐请求列入迁移报告；用真实请求接收端比较导入前后的 method、URL、Header、Body。补充导入→导出→再导入的保真回归。

### P1：恢复可验证的性能预算

本次 `pnpm build` 后，从 Vite manifest 入口只沿静态 imports 收集 JS/CSS，逐文件 gzip level 9 求和：**279,930 字节，273.4 KiB**。预算为 **153,600 字节，150 KiB**，超出 **82.2%**。该结果不包含动态加载分支，也不代表冷启动时间或内存量测。

`src/shell/RootShell.vue:4` 静态引入 `AppBody`；后者继续引入请求/响应面板。静态依赖中可见 AppSelect、Scrollbar、Popover 等较重组件。当前 CI 包含构建和质量检查，但没有执行 S1/S3/S5 或按性能预算失败的步骤；Vite 的 chunk 警告也不是首屏 gzip 门禁。

完善标准：调整 Launcher/工作区及 UI 组件的加载边界，测得首屏 gzip ≤150 KiB；CI 超限失败。冷启动、内存、50 标签、大响应与安装包分别使用对应脚本重测，不能引用旧 Spike 代替当前产物。

| 顺序 | 工作项 | 最小可验收闭环 |
| --- | --- | --- |
| 1 | Cookie 会话管理 | `Set-Cookie` 接收→域/路径/过期规则存储→后续请求自动携带→查看/编辑/删除→请求级关闭。当前 `cookies.rs` 无执行链调用，`sendCookies` 字段尚未驱动发送行为；响应 Cookie 展示和 API Key Cookie 不能替代 Jar |
