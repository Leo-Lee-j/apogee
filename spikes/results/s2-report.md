## 发现

1. **R13 的 9.1× 膨胀已消除。** SpanIndex 每节点固定 32 字节，只存 parent/children/key-id/kind/value span；对象键全局去重，数组下标内联。10MB 合成响应的结构自报 17.57 MB（1.76×），进程私有内存增量 18.20MB（1.82×）。

2. **完整 body 不再进入 Rust 堆。** Tauri 对发布后不可变的 spool 文件建立只读 mmap，扫描完成立即解除映射；树分页只按标量 span 读取最多 4KB。该行为同时由源码结构和 SpanIndex 元数据值验证。

3. **内存下降换来索引构建变慢。** 10MB 从 196.0ms 增至 689.2ms。当前扫描器先完整校验/计数，再按容器建立连续子节点区间，会重复扫描嵌套内容。索引是 2MB 以上显式操作，不影响 26.7ms 首屏；后续若要优化，应保留 32B 节点布局，改为单次 token 流 + 紧凑重排，而不是恢复 Value。

4. **Range 首屏仍与 body 体积无关。** 四档耗时 4.0 / 3.7 / 3.2 / 2.7ms，范围 2.7–4.0ms；100MB 仍只读取 64KB。

5. **LRU 与 Cold 释放已落地。** 索引缓存默认预算 128MB，超限淘汰最久未使用索引；标签转 Cold 可调用 `drop_index`，正在分页的 Arc 请求可安全完成。50MB/100MB 继续按 SummaryOnly 产品规则跳过索引。

## 后续

1. 保留当前 SummaryOnly 硬阈值；SpanIndex 降低了显式解析代价，但不应因此让 50MB+ 默认建树。
2. 将 `indexMetadataRatio < 3` 和 32B 节点布局保留为 R13 回归守门；进程差值只作辅助观测。
3. 索引构建耗时可在 v0.2 树视图阶段单独优化，不阻塞当前 S2 首屏验收。
